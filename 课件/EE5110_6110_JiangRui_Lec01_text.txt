What is an Event-based Vision Sensor (EVS)?
[Lichtsteiner, Posch, Delbruck, A 128x128 120 dB 15µs Latency Asynchronous Temporal Contrast Vision Sensor , 2008
http://rpg.ifi.uzh.ch/docs/scaramuzza/Tutorial_on_Event_Cameras_Scaramuzza.pdf
• Novel sensor that measures only pixel-wise brightness 
change
• First commercialized in 2008 by T. Delbruck (UZH&ETH) 
under the name of Dynamic Vision Sensor (DVS)
• Low-latency (~ 1 μs)
• No motion blur
• High dynamic range (140 dB instead of 60 dB)
• Ultra-low power (mean: 1mW vs 1W)
Traditional vision algorithms 
cannot be used because: 
• Asynchronous pixels 
• No intensity information (only 
binary intensity changes)

Influence of Event Representation on Data Rate
• Exercise: Suppose each pixel triggers 1 time per second on average; 
The resolution of the sensor is 1 Mega Pixels. 
Event (x, y, p, t) encoding is (uint10, uint10, binary, uint32).
• Calculate and compare the data rate for:
▪ event point cloud
▪ 30 fps event binary frames (binary)
▪ 30 fps event count frames (uint8)
Solution:
We may firstly compute how many bits required to represent one event:
10+10+1+32 = 53 bits
In total, the data rate for raw events is:
53 bits/evt x 1 M evts/s = 53 M bits/s

Solution:
For event binary frames, 30 fps data rate equals to
30 fps x 1M pixels/frame x 1 bit/pixel = 30M bits/s

Note:
• The data rate for event frames does not change w.r.t. event rate, with a

→ Data rate more stable. Good or bad? Depending on your algorithm!

triggers 10 times per second?
→ The event frame representation will have much smaller data rate!
